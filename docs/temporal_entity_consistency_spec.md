# Temporal Entity Consistency Metrics

## 1. Purpose

This document specifies two metrics for evaluating the temporal consistency of
the entities produced by the object-detection and tracking stage:

1. **Mean Track Continuity (MTC)**, which measures interruptions within
   individual tracks.
2. **Object Count Consistency (OCC)**, which measures the stability of the
   number of simultaneously active tracks for each object class.

The metrics operate exclusively on the JSON files already generated by the
pipeline. They do not read video frames, rerun a detector, or use detection
confidence scores. Both metrics range from 0 to 1, and higher values indicate
greater temporal consistency.

These metrics assess the consistency of the pipeline's detected and tracked
entities. They do not constitute appearance-based object or person
re-identification.

## 2. Input contract

By default, the implementation copies `video_general_obj_det_finished.zip`
from Google Drive to `/content/video_general_obj_det_finished.zip` before
processing it. It also accepts an explicitly configured local archive or its
extracted `video_general_obj_det_finished` directory. ZIP input is extracted
to a temporary directory before evaluation. Each input JSON file must contain a
`detected_objects` mapping. Each entry in
the mapping represents one track and must provide:

- `class_name`: the semantic class assigned to the track;
- `track_id`: the persistent identifier assigned by the tracking stage;
- `bbox`: a frame-aligned list containing either a bounding box or `null`.

For example:

```json
{
  "detected_objects": {
    "knife_1004": {
      "class_name": "knife",
      "track_id": 1004,
      "bbox": [
        [0.21, 0.32, 0.40, 0.61],
        [0.22, 0.33, 0.41, 0.62],
        null
      ]
    }
  }
}
```

A track is considered **active** in frame \(t\) when its `bbox[t]` value is not
`null`. Bounding-box coordinates are not otherwise used by these metrics.

Malformed track entries and tracks without any valid observation are excluded
and reported by the implementation.

## 3. Mean Track Continuity

### 3.1 Per-track continuity

For track \(i\), let \(f_i\) and \(l_i\) denote the first and last frames in
which the track is active. Its temporal span is:

\[
S_i = l_i - f_i + 1.
\]

Let \(a_i(t)\) equal 1 when track \(i\) is active in frame \(t\), and 0
otherwise. Track Continuity is defined as:

\[
TC_i = \frac{\sum_{t=f_i}^{l_i} a_i(t)}{S_i}.
\]

Consequently, entry into or exit from the scene does not reduce continuity;
only missing observations between the first and last observations do. A track
observed in every frame of its span has \(TC_i=1\).

### 3.2 Video-level aggregation

For a video containing \(N\) valid tracks, Mean Track Continuity is the
unweighted macro-average:

\[
MTC = \frac{1}{N}\sum_{i=1}^{N}TC_i.
\]

Every track therefore contributes equally, irrespective of its duration or
class. If a video contains no valid tracks, MTC is undefined and is reported as
missing rather than as zero.

### 3.3 Interpretation

- A high MTC indicates that individual track identifiers are maintained with
  few internal gaps.
- A low MTC indicates frequent loss and recovery of tracked entities.
- A one-frame track has continuity 1 by definition. The number of tracks and
  their spans must therefore be reported alongside MTC to make short or
  fragmented detections visible.

## 4. Object Count Consistency

### 4.1 Per-frame object count

For class \(c\), the number of active tracks in frame \(t\) is:

\[
n_c(t) = \sum_{i:\,class(i)=c} a_i(t).
\]

Let \(f_c\) and \(l_c\) be the first and last frames for which
\(n_c(t)>0\). Only the inclusive interval \([f_c,l_c]\) is evaluated, so the
metric does not penalize a class before its first appearance or after its last
appearance.

### 4.2 Reference count

The reference count \(\hat{n}_c\) is the mode of the strictly positive counts
observed inside the evaluation interval:

\[
\hat{n}_c = \operatorname{mode}\{n_c(t) \mid f_c \leq t \leq l_c,
n_c(t)>0\}.
\]

Zero-count frames are excluded when estimating the reference count so that
missing detections cannot become the expected state. They remain included in
the subsequent consistency calculation and therefore reduce the score. If
multiple positive counts have the same maximum frequency, the smallest count
is selected deterministically.

### 4.3 Per-class consistency

Object Count Consistency for class \(c\) is:

\[
OCC_c = \frac{1}{l_c-f_c+1}
\sum_{t=f_c}^{l_c}\mathbb{1}[n_c(t)=\hat{n}_c].
\]

The score decreases when entities disappear, appear spuriously, or are
duplicated relative to the class's modal positive count.

### 4.4 Video-level aggregation

For the set \(C\) of classes observed in the video, video-level OCC is the
unweighted macro-average:

\[
OCC = \frac{1}{|C|}\sum_{c\in C}OCC_c.
\]

Each observed class contributes equally. If no class is observed, OCC is
undefined and is reported as missing.

## 5. Dataset-level aggregation

For a collection of videos, the primary dataset scores are macro-averages of
the available video-level scores:

\[
MTC_{dataset} = \frac{1}{|V_{MTC}|}\sum_{v\in V_{MTC}}MTC_v,
\qquad
OCC_{dataset} = \frac{1}{|V_{OCC}|}\sum_{v\in V_{OCC}}OCC_v.
\]

This gives every video equal weight. The implementation also exports all
track-level and class-level results, allowing alternative weighted summaries
to be computed if required.

## 6. Required reporting

An evaluation should report at least:

- dataset-level MTC and OCC;
- per-video MTC and OCC;
- number of valid tracks and observed classes per video;
- per-track continuity and temporal span;
- per-class OCC, reference count, and evaluated interval length;
- skipped files or malformed entries.

Scores should be presented separately rather than combined into a single
index: MTC captures within-track interruptions, whereas OCC captures changes
in the number of active entities.
